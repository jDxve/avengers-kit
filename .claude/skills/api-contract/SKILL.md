# API contract

One chain carries the API from a Zod schema on the server to every client, and this skill covers the links between the stacks and the checks that hold them together. The rules themselves live in the stack standards, and this skill links them rather than restating them. The repo's established convention beats this skill, and you say so when they differ. Drizzle and Zod are the exception: repo convention never overrides them, and a repo that differs is flagged for migration.

## The chain

1. Zod schema in the module, `.strict()` on requests ([nestjs 4.3](../nestjs-standards/references/05-rules.md)).
2. `createZodDto` turns it into the DTO that the validation pipe and `@nestjs/swagger` both read.
3. OpenAPI document from `SwaggerModule.createDocument`, passed through `cleanupOpenApiDoc`.
4. Committed `openapi.json`, or a pinned versioned URL. Never a live dev server ([react 11.6](../react-standards/references/12-enforcing-this-automatically.md)).
5. Web: `openapi-typescript` writes `src/lib/api/types.gen.ts` ([react section 2 (`03-stack.md`)](../react-standards/references/03-stack.md), [section 3 (`04-structure.md`)](../react-standards/references/04-structure.md)).
6. Flutter: hand-written `retrofit` DTOs, checked by a decode test against `openapi.json` ([flutter "Stack" (`04-stack.md`)](../flutter-standards/references/04-stack.md)). No generated Dart client.

Change the schema, regenerate, commit. The diff of `openapi.json` and `types.gen.ts` is the API review. CI fails when either is stale (`openapi:check` in [nestjs section 10 (`11-enforcing-this-automatically.md`)](../nestjs-standards/references/11-enforcing-this-automatically.md), `api:check` in react 11.6).

## Rules that never bend

- One error shape `{ code, message, requestId }`. Clients branch on `code`, never on `message`. Owner: [nestjs 4.3](../nestjs-standards/references/05-rules.md), mapped by the exception filter in 4.6; clients per [react 4.4](../react-standards/references/05-rules.md).
- Within a version, only additive optional fields. Removing or renaming a field, tightening validation, or changing an error code is breaking. Owner: nestjs 4.3; caught in review of the `openapi.json` diff.
- A breaking change needs a new version or a deprecation window recorded in the contract. Format in `04-errors-and-versioning.md`; checked by review against the contract.
- Every list endpoint has a stable sort, a maximum page size, and a documented cursor or offset. Owner: [nestjs section 11 (`12-api-behavior-and-external-dependencies.md`)](../nestjs-standards/references/12-api-behavior-and-external-dependencies.md) "HTTP"; the maximum is enforced by the query schema.
- A non-idempotent write that can be retried carries one `Idempotency-Key` per user intent, reused on retry. Owners: [nestjs section 6 (`07-concurrency-and-data-integrity.md`)](../nestjs-standards/references/07-concurrency-and-data-integrity.md) item 4; [flutter section 5 (`10-feature-anatomy-worked-example-auth.md`)](../flutter-standards/references/10-feature-anatomy-worked-example-auth.md) "data/services (Retrofit)" for Flutter, including reuse on retry; [react 4.5](../react-standards/references/05-rules.md) for sending a key on irreversible or financial actions. Reuse on retry on web is a kit rule. Proven by a two-request e2e test.
- Installed mobile clients keep sending old request fields. A removed request field stays accepted until the minimum supported app version no longer sends it. Owner: nestjs 4.3; the contract names that version.

## Output: the contract's API section

Link the OpenAPI operation; do not copy its schema. One row per operation:

```markdown
## API

Spec: `openapi.json` at <commit or pinned URL>. Version: v1.

| Operation | operationId | Codes the client branches on | Idempotency-Key | Pagination |
| --- | --- | --- | --- | --- |
| `POST /orders` | `createOrder` | `ORDERS_OUT_OF_STOCK`, `ORDERS_LIMIT_REACHED` | required, 24 h | n/a |
| `GET /orders` | `listOrders` | none | n/a | cursor, `createdAt desc, id desc`, max 100 |

- Breaking changes: none. (Or one row per change in the Deprecations table, `04-errors-and-versioning.md`.)
- Minimum supported mobile app version: <version>.
```
